# PDF検索ハイライト Chrome拡張 仕様書

作成日: 2026-10-22 / ステータス: ドラフト(dig による壁打ちの結果を整理したもの)

## Problem Statement

Chrome 標準のビューアで PDF を開き、検索(Ctrl+F)で単語がヒットしても、その箇所がページ上のどこにあるのか分かりにくいことがある。ヒット箇所をひと目で見つけられるように、強く目立たせたい。

これまで、検索語を入力させて該当箇所を黄色くするブックマークレットを試したが、期待どおりに動作しなかった。原因は、Chrome 標準の PDF ビューアが、ブックマークレットの実行や、ページ内テキストへの `window.find` / `designMode` といった DOM 操作を受け付けない作りであることにある。そのため、コードの修正では解決できず、方式そのものの変更が必要である。

## Solution

Chrome 拡張として、Web 上の `.pdf` を開いたときに、拡張に同梱した pdf.js ビューアへ自動で転送する。pdf.js ビューアでは、検索語に一致した箇所がテキストレイヤー上の要素として描画されるため、スタイルで目立たせることができる。

- 検索語に一致するすべての箇所を、蛍光イエローで強調する
- 現在選択されているヒットを、赤枠で囲む
- ヒットを切り替えるたびに、現在のヒットの赤枠を数回点滅させ、その後は赤枠のみ固定で残す

利用者は、PDF を開く手順を変えずに(URL を開くだけで)、これまでと同じ感覚で検索できる。

## User Stories

1. As a PDF 閲覧者, I want Web 上の `.pdf` の URL を開いただけで自動的にハイライト対応のビューアで表示してほしい, so that 毎回手動でビューアを切り替えずに済む
2. As a PDF 閲覧者, I want 検索語に一致するすべての箇所が蛍光イエローで強調されてほしい, so that ページ内のどこにヒットがあるかをひと目で把握できる
3. As a PDF 閲覧者, I want 現在選択されているヒットが赤枠で囲まれてほしい, so that 数あるヒットの中でいま注目すべき箇所を見失わない
4. As a PDF 閲覧者, I want 次のヒットや前のヒットへ移動した直後に、現在のヒットの赤枠が数回点滅してほしい, so that 画面が切り替わった直後でも視線を引きつけられる
5. As a PDF 閲覧者, I want 点滅が数回で止まり、その後は赤枠が固定で残ってほしい, so that 文章を読むときに点滅が視線の邪魔にならない
6. As a 視覚的な動きが苦手な閲覧者, I want OS の「視覚効果を減らす」設定がオンのときは点滅しないでほしい, so that 不快感なく利用できる
7. As a PDF 閲覧者, I want 検索バーの「すべて強調表示」が最初からオンになっていてほしい, so that 毎回チェックを入れる手間がない
8. As a PDF 閲覧者, I want 標準の検索バー(Ctrl+F)をそのまま使えてほしい, so that 新しい操作を覚えなくてよい
9. As a PDF 閲覧者, I want 1 つのヒットが行の折り返しをまたいでいても、赤枠が途切れずに見えてほしい, so that 長い語句でもヒット範囲を正しく認識できる
10. As a PDF 閲覧者, I want 同じ検索語でヒットが多数あっても、現在のヒットだけが他と明確に区別されてほしい, so that 何件ヒットしていても現在位置が分かる
11. As a PDF 閲覧者, I want 普段開く Web 上のどのサイトの PDF でも転送されてほしい, so that サイトごとの設定をしなくてよい
12. As a PDF 閲覧者, I want ログインが不要な公開 PDF が、拡張を入れても今までどおり開けてほしい, so that 日常の閲覧が妨げられない
13. As a PDF 閲覧者, I want PDF のダウンロードや印刷など、pdf.js ビューアに標準で備わる機能が引き続き使えてほしい, so that 閲覧以外の用途にも困らない
14. As a 開発者, I want 同梱する pdf.js を公式配布ビルドそのままにして、本体への変更を最小限(追加のスタイルとスクリプトを読み込ませる 2 行と、オリジンチェックの 1 か所)にしたい, so that pdf.js を更新するときの差分が小さく済む
15. As a 開発者, I want ハイライトの見た目を、本体とは別の追加スタイルにまとめたい, so that 色や枠線を調整するときに本体を触らずに済む
16. As a 開発者, I want 「すべて強調表示」を初期オンにする処理を、追加スクリプトに分けたい, so that 本体の挙動を変えずに初期状態だけを制御できる
17. As a 開発者, I want PDF かどうかの判定ロジックと、ビューアへ転送するロジックを分けておきたい, so that 将来、拡張子以外(Content-Type)でも PDF を判定したくなったときに、判定だけを差し替えられる
18. As a 開発者, I want 拡張に必要な権限と、その理由を README に明記したい, so that GitHub で公開したときに、利用者が納得して導入できる
19. As a 開発者, I want pdf.js のライセンス(Apache 2.0)の表記を同梱したい, so that 公開時にライセンス上の問題を避けられる
20. As a 開発者, I want 拡張をパッケージ化せずに自分の Chrome に読み込んで使い始めたい, so that 審査や配布の手間なく、すぐ動作確認ができる
21. As a 開発者, I want 拡張が PDF を外部サーバーへ送信しないことを保証したい, so that 閲覧した PDF の内容が第三者へ渡る不安がない
22. As a 開発者, I want 将来、必要になったときに「標準ビューアへ戻す」切り替え機能を足せる構造にしておきたい, so that 最初は単純に作り、あとから拡張できる
23. As a PDF 閲覧者, I want 拡張を一時的に無効にすれば Chrome 標準のビューアに戻れてほしい, so that 切り替え機能がなくても、困ったときの逃げ道がある
24. As a 開発者, I want 拡張の動作を自動テストで検証したい, so that pdf.js の更新やスタイル変更のあとでも、ハイライトが壊れていないことを確認できる

## Implementation Decisions

- **方式**: 元のブックマークレットは破棄し、Chrome 拡張として作り直す。拡張が Web 上の PDF を、拡張自身が同梱する pdf.js ビューアへ転送する。
- **pdf.js の組み込み**: pdf.js の公式配布ビルドを同梱し、付属のビューアをそのまま使う。pdf.js リポジトリの Chromium 向け拡張サンプルのフォークや、ビューア UI の自作は行わない。
- **pdf.js 本体への変更**: ビューアの HTML に、追加スタイルと追加スクリプトを読み込む 2 行を追記し、ビューアのスクリプトのオリジンチェックに、拡張自身のオリジンを許可する 1 か所の変更を加える(合計 3 か所)。それ以外の本体ファイルは変更しない。オリジンチェックの変更が必要な理由は、pdf.js が、ビューアと異なるオリジンの PDF を開くことを拒否するため(pdf.js 6.4.299 のコードで確認済み)。この方針は README に明記する。pdf.js の更新は、配布ビルドの差し替えと、この 3 か所のパッチの再適用(スクリプトで自動化)で行う想定とする(更新の運用は、手動での入れ替えを想定した仮置きであり、利用者から明示的な回答は得ていない)。
- **転送の対象**: 当面は、URL が `.pdf` で終わる Web 上の PDF のみ。
- **判定と転送の分離**: 「その URL を転送するかを判定する部分」と「ビューアへ転送する部分」を別のモジュールとして分け、判定部分だけを差し替えられる構造にする。将来は Content-Type による判定を足せるようにしておく(今回は実装しない)。
- **転送の仕組み**: Manifest V3 の宣言的なリクエスト書き換え(`declarativeNetRequest` のリダイレクト)を第一候補とする。Manifest V3 を前提にするのは、現行の Chrome で読み込める形式にするためで、利用者と確認した事項ではなく、私の想定である。
- **ホスト権限**: `host_permissions` に `http://*/*` と `https://*/*` を静的に宣言する。任意のサイトの PDF を転送し、ビューアから取得する必要があるため、権限を絞る案(サイトごとの任意権限、特定ドメインのみ)は採用しない。
- **検索 UI**: pdf.js 標準の検索バーをそのまま使う。独自の入力 UI(元のブックマークレットの `prompt` のようなもの)は作らない。検索バーの「すべて強調表示」は、追加スクリプトで初期オンにする。
- **ハイライトの見た目**:
  - 全ヒット: 蛍光イエローの背景。色の具体値は、実装時に実際の見え方を確認して調整する。
  - 現在のヒット: 赤枠。枠線は、レイアウトがずれにくい方式(アウトラインや影)で表現する。
  - 点滅: 現在のヒットが切り替わるたびに 2〜3 回点滅し、その後は赤枠のみ固定で残す。
  - 視覚効果の軽減: OS の「視覚効果を減らす」設定がオンの場合は、点滅せず、赤枠のみにする。
  - 折り返しまたぎ: 1 つのヒットが複数の要素に分かれる場合でも、枠線が途切れて見えないようにスタイルを調整する。
- **利用範囲と配布**: まずは自分の Chrome で、パッケージ化されていない拡張として読み込んで使う。将来、GitHub で公開する可能性がある。公開時は、README に権限の理由と、通信を外部に送らないことを記載し、pdf.js のライセンス表記を同梱する。
- **切り替え機能**: 標準ビューアへ戻すためのオン/オフ切り替えや、サイトごとの除外リストは、最初は作らない。困ったときは拡張を一時的に無効にする。

## Testing Decisions

- **良いテストの条件**: 内部の実装(どのクラスを付与するか、どの関数を呼ぶか)ではなく、外部から観測できる振る舞い(転送されること、ハイライトが画面に出ること、点滅が止まること)だけを検証する。
- **テストの境界(シーム)**: 最上位の 1 か所だけとする。「拡張を読み込んだ Chromium を自動操作し、テスト用のローカルサーバーが配信する PDF を開いて、ビューア画面の状態を検証する」ことをシームとする。判定ロジックなど内部モジュール単体のテストは、この段階では作らない。
- **検証する振る舞い**:
  - `.pdf` で終わる URL を開くと、自前のビューアへ転送される
  - 検索すると、全ヒットが蛍光イエローで強調される
  - 現在のヒットだけが赤枠で囲まれ、次のヒットへ移動すると赤枠が移る
  - 現在のヒットは、切り替え直後に点滅し、その後は赤枠のみが固定で残る
  - 視覚効果を減らす設定がオンのときは、点滅しない
  - 「すべて強調表示」が、最初からオンになっている
  - `.pdf` で終わらない URL は転送されない
- **先行事例**: 現時点で既存のコードベースはなく、参考にできる既存テストはない。

## Out of Scope

- Content-Type による PDF 判定(拡張子のない URL への対応)。将来の拡張とし、今回は実装しない
- 標準ビューアへ戻す切り替え機能(オン/オフ、サイト単位の除外リスト)
- ログインが必要な PDF(社内システムなど)への対応
- ローカルファイル(`file://`)の PDF。普段開く PDF が Web 上のものが中心であるため、当面は対象外とする
- Chrome ウェブストアでの一般公開(審査やプライバシーポリシーの対応)
- Chrome 以外のブラウザへの対応
- 検索 UI の自作、および PDF への注釈や保存の機能

## Further Notes

- **実装前に確認が必要な事項**(いずれも私の認識で、未検証):
  - 同梱する pdf.js のバージョンで、検索ヒットに付与されるクラス名(全ヒット用、現在のヒット用、折り返しの先頭・中間・末尾用)と、「すべて強調表示」のチェックボックスの ID が、想定どおりであること
  - 拡張ページ(`chrome-extension://`)から他サイトの PDF を取得するとき、pdf.js 側のオリジンチェックで弾かれる(pdf.js 6.4.299 のコードで確認済み)。回避のため、本体に 1 か所のパッチを当てた。実ブラウザでの動作は未確認
  - `declarativeNetRequest` のリダイレクトに必要なホスト権限の条件が、想定どおりであること
- 設計の議論の中で、「`host_permissions` を必要最小限に絞る」と一度案内したが、任意のサイトの PDF を転送する用途には当てはまらないため訂正した。本仕様では、全サイトの権限を前提としている。
